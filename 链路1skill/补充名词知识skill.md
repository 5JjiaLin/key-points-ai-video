# 科普视频知识断层识别 Skill v1：单句 Top1 优先级版

## 1. Skill 定位

本 Skill 只负责识别科普视频文案中的**知识断层**：

> 视频使用了普通用户可能不理解的概念、术语、分类、缩写或专业表达，视频又没有及时解释；如果用户不理解它，会影响对当前结论或后续内容的理解。

本 Skill 的任务不是寻找所有生僻词，而是从字幕、OCR 与上下文中筛选出：

1. 普通用户可能不懂；
2. 视频没有讲清；
3. 对理解主线确实重要；
4. 能用一句话准确补懂；
5. 值得在对应时间点出现轻提示；

的知识断层。

本 Skill 用于第一条产品链路：

```text
视频正常播放
→ 播放到知识断层所在语句
→ 在自然停顿处出现轻提示
→ 用户点击后查看一句话解释与必要补充
```

---

## 2. 与其他链路的严格边界

### 2.1 属于知识断层

用户不知道某个词、分类或专业表达是什么意思。

例：

```text
“胃肠功能紊乱”是什么意思？
“2A类致癌物”是什么意思？
“做空”是什么意思？
“IARC”是什么？
```

### 2.2 不属于知识断层：抽象数据直观化

用户知道数字字面意思，但缺少现实尺度感。

例：

```text
65℃有多烫？
8000亿美元有多少？
风险增加20%意味着什么？
```

路由：

```yaml
route: abstract_data_visualization
```

### 2.3 不属于知识断层：视频说法验证

用户不是不懂词义，而是不知道视频说法是否准确。

例：

```text
冰水就是不健康的，这句话准确吗？
运动后绝对不能喝冰水吗？
喝一次65℃热饮就会致癌吗？
```

路由：

```yaml
route: claim_verification
```

### 2.4 边界判断口诀

```text
不知道“这个词是什么”
→ 知识断层

知道词义，但不知道“到底多大、多热、多快”
→ 抽象数据直观化

知道句子意思，但不知道“说得对不对”
→ 视频说法验证
```

## 3. 输入

```yaml
video_id: string
title: string
description: string

asr_segments:
  - start_ms: integer
    end_ms: integer
    text: string

ocr_segments:
  - start_ms: integer
    end_ms: integer
    text: string

chapter_info: optional
domain_hint: optional
comments_summary: optional
```

### 3.1 输入要求

1. ASR 必须保留时间戳；
2. 不允许只看单个词，至少读取候选句前后各 10～15 秒；
3. OCR 只作为辅助信息；
4. 必须识别完整语义句，而不是机械按字幕行切分；
5. 需要检查作者后文是否马上解释该概念；
6. 评论区“什么意思”“没听懂”等信号只能提高优先级，不能单独决定触发。

## 5. 第一阶段：提取知识断层候选

只有以下内容可以进入候选池。

### 5.1 专业术语

来自医学、科技、金融、历史、心理、法律等领域的专业表达。

例：

- 胃肠功能紊乱
- 胰岛素抵抗
- 板块俯冲
- 熵增
- 流动性陷阱
- 机会成本
- 应激反应

---

### 5.2 分类、等级与标准名称

用户认识字面，但不知道该等级代表什么。

例：

- 2A类致癌物
- 一级响应
- 三级甲等医院
- B1语言水平
- 一级市场
- 800V平台

---

### 5.3 缩写、英文简称与机构简称

例：

- IARC
- GDP
- CPI
- ROI
- REM
- ASR
- LLM

注意：

> 缩写陌生不代表必须触发。只有当不理解该缩写会影响当前结论时，才进入高优先级。

---

### 5.4 行业黑话

在特定行业中具有特殊含义的表达。

例：

- 做空
- 抄底
- 冷启动
- 私域
- 去杠杆
- 护城河
- 向上管理

---

### 5.5 历史、制度与文化概念

例：

- 荫封
- 察举制
- 门阀
- 摄政
- 郡县制
- 外戚

---

### 5.6 状态与机制名称

用户知道它是某种状态，却不知道具体指什么。

例：

- 功能紊乱
- 炎症反应
- 神经兴奋
- 代谢异常
- 肌肉痉挛
- 认知失调

注意：

```text
“功能紊乱是什么意思？”
→ 知识断层

“功能紊乱时，胃肠具体怎么变化？”
→ 抽象机制具体化，不属于本 Skill
```

---

### 5.7 理解后文必需的前置概念

有些词不算极端生僻，但视频后续论证依赖它。

例：

> “短暂不适不等于胃黏膜损伤。”

若用户不理解“胃黏膜损伤”，就可能把身体不适直接理解为器官被破坏。

---

### 5.8 容易歧义或被过度理解的概念

例：

- 风险
- 损伤
- 敏感
- 炎症
- 致癌物
- 有效
- 长期

这些词只有在专业语境与日常理解存在明显差异时，才进入候选。

---

## 6. 第二阶段：知识断层硬门槛

每个候选必须同时通过以下 5 个条件。任意一项不满足，直接淘汰，不参与优先级评分。

### 门槛 1：普通用户可能不理解

判断依据：

- 属于专业词典或行业术语；
- 普通语料中出现频率低；
- 是分类、等级、缩写或制度名称；
- 历史评论或搜索数据中经常出现“什么意思”；
- 需要学科背景才能准确理解。

不合格：

- 胃
- 温度
- 睡眠
- 运动
- 喝水

除非它们在当前语境中具有特殊专业含义。

---

### 门槛 2：视频没有解释清楚

必须检查候选概念：

- 前 5～10 秒；
- 后 8～15 秒；
- 当前完整语义段；
- 同期 OCR 和图示。

作者已经解释的信号：

```text
也就是
指的是
简单来说
换句话说
所谓
比如
可以理解为
```

也包括：

- 明确定义句；
- 生活化例子；
- 画面标注；
- 对比说明；
- 结构示意图。

示例：

> “胃黏膜，也就是胃内壁的一层保护组织。”

处理：

```yaml
video_already_explained: true
should_trigger: false
```

---

### 门槛 3：不理解会影响主线

进行“删除测试”：

> 假设用户完全不知道该概念，是否仍然能正确理解当前句子的核心结论？

如果仍能理解，则降级或淘汰。

例：

> “IARC将高温饮品列为2A类致癌物。”

- 不懂 IARC，仍可大致理解结论；
- 不懂 2A类致癌物，无法准确理解风险分类。

因此“2A类致癌物”更值得触发。

---

### 门槛 4：当前语境中的词义明确

以下情况不得自动触发：

- ASR 识别可能错误；
- 同一词在当前语境中有多种解释；
- 缺少完整上下文；
- 无法确定具体指代对象；
- 解释只能靠猜测。

---

### 门槛 5：可以轻量解释

必须能够做到：

- 一个清晰问题；
- 一句话定义；
- 最多一个必要例子；
- 不引入多个更难的新术语。

若必须写成长篇背景才能讲清，则不自动触发。

---

## 7. 第三阶段：同一句多个候选时只选择 Top1

### 7.1 硬规则

```text
同一个完整语义句中，无论识别出多少个知识断层候选，
最终最多只选择 1 个进行自动触发。
```

禁止：

- 合并两个概念生成一个问题；
- 连续弹出两个知识断层提示；
- 在同一句中分别生成两张卡；
- 因为两个词都陌生就全部展示。

其他候选只保留在内部调试数据中，不生成当前轻提示。

```yaml
sentence_level_top1: true
secondary_candidate_display: false
```

---

## 8. Top1 优先级打分

每个通过硬门槛的候选概念，按照 100 分制评分：

```text
总分 =
主线理解必要性 35分
+ 误解风险 25分
+ 用户陌生度 20分
+ 后续依赖程度 10分
+ 单次解释收益 10分
```

---

### 8.1 主线理解必要性：0～35分

判断问题：

> 不理解这个概念，用户还能否正确理解这句话的核心结论？

| 分数 | 标准 |
|---:|---|
| 35 | 不理解就无法理解核心结论 |
| 28 | 会明显误解因果、对象或结论 |
| 20 | 能理解大意，但会遗漏重要信息 |
| 10 | 只是辅助背景 |
| 0 | 删除后几乎不影响理解 |

这是权重最高的维度。

---

### 8.2 误解风险：0～25分

判断问题：

> 用户理解错这个概念，会造成多严重的认知偏差？

| 分数 | 标准 |
|---:|---|
| 25 | 可能把结论理解反，或导致错误行动 |
| 20 | 容易夸大或缩小风险 |
| 12 | 会产生明显理解偏差 |
| 5 | 只影响少量细节 |
| 0 | 基本不会造成误解 |

高风险领域包括：

- 医疗健康；
- 食品安全；
- 金融；
- 法律；
- 人身安全。

---

### 8.3 用户陌生度：0～20分

判断问题：

> 普通用户不知道这个概念的概率有多高？

| 分数 | 标准 |
|---:|---|
| 20 | 冷门分类、缩写或专业学术术语 |
| 16 | 明显专业术语 |
| 12 | 半专业词，部分用户知道 |
| 6 | 日常中偶尔出现 |
| 0 | 普通常识词 |

注意：

> 陌生度不能单独决定触发。一个极其陌生但无关紧要的机构缩写，不应压过承载核心结论的概念。

---

### 8.4 后续依赖程度：0～10分

判断问题：

> 后面的视频是否继续依赖这个概念？

| 分数 | 标准 |
|---:|---|
| 10 | 后续多个知识点都依赖它 |
| 7 | 后续重复使用或继续展开 |
| 4 | 只影响紧接着的一小段 |
| 0 | 只出现一次，后续不再使用 |

---

### 8.5 单次解释收益：0～10分

判断问题：

> 用一句话解释后，能否立刻帮助用户继续看懂视频？

| 分数 | 标准 |
|---:|---|
| 10 | 一句话即可明显消除断层 |
| 7 | 一句话加一个简单例子可以讲清 |
| 4 | 需要较多背景 |
| 0 | 无法用轻量卡片准确解释 |

---

## 9. 触发阈值

```yaml
total_score >= 70:
  should_trigger: true
  display_mode: auto_prompt

55 <= total_score < 70:
  should_trigger: false
  display_mode: internal_candidate

total_score < 55:
  should_trigger: false
  display_mode: discard
```

说明：

- 同一句只选择最高分候选；
- 即使它是最高分，低于 70 分也不自动触发；
- 第二名无论分数多高，都不在同一句中触发；
- 第二名只保留在内部候选记录中，默认不进入前端列表。

---

## 10. 分数接近时的决胜规则

即使两个候选只差 1 分，也只选择一个。

按以下顺序决胜：

```text
1. 主线理解必要性更高
2. 误解风险更高
3. 后续依赖程度更高
4. 用户陌生度更高
5. 单次解释收益更高
```

五项仍完全相同时，按语义角色选择：

```text
核心结论概念
>
核心因果概念
>
状态或机制概念
>
条件概念
>
来源机构、人物、地名或背景概念
```

若仍无法稳定区分：

```yaml
decision: no_auto_trigger
reason: ambiguous_priority
```

宁可不弹，也不要随机选择。

## 11. 多候选评分示例

### 11.1 机构与分类概念

原句：

> IARC将高温饮品列为2A类致癌物。

候选：

- IARC
- 2A类致癌物

| 维度 | IARC | 2A类致癌物 |
|---|---:|---:|
| 主线理解必要性 | 8 | 35 |
| 误解风险 | 2 | 25 |
| 用户陌生度 | 19 | 17 |
| 后续依赖 | 2 | 8 |
| 单次解释收益 | 8 | 10 |
| **总分** | **39** | **95** |

最终选择：

```yaml
selected_term: 2A类致癌物
prompt_title: 2A类致癌物是什么意思？
```

不触发：

```text
IARC是什么？
```

---

### 11.2 两个机制概念

原句：

> 低温刺激可能影响胃肠蠕动和自主神经反应。

假设后文主要讲胃部不适：

| 维度 | 胃肠蠕动 | 自主神经反应 |
|---|---:|---:|
| 主线理解必要性 | 34 | 20 |
| 误解风险 | 18 | 14 |
| 用户陌生度 | 13 | 18 |
| 后续依赖 | 9 | 4 |
| 单次解释收益 | 9 | 6 |
| **总分** | **83** | **62** |

最终选择：

```yaml
selected_term: 胃肠蠕动
prompt_title: 胃肠蠕动是什么？
```

---

### 11.3 状态与结构概念

原句：

> 这更可能是胃肠功能紊乱，而不是胃黏膜损伤。

假设当前段落重点解释短暂不适：

| 维度 | 胃肠功能紊乱 | 胃黏膜损伤 |
|---|---:|---:|
| 主线理解必要性 | 35 | 29 |
| 误解风险 | 24 | 22 |
| 用户陌生度 | 17 | 12 |
| 后续依赖 | 9 | 5 |
| 单次解释收益 | 10 | 8 |
| **总分** | **95** | **76** |

最终选择：

```yaml
selected_term: 胃肠功能紊乱
prompt_title: 功能紊乱是什么？
```

不合并为：

```text
功能紊乱和胃黏膜损伤有什么区别？
```

## 12. 整条视频中的去重

### 12.1 同一概念重复出现

```text
第一次重要出现
→ 可触发

后续重复出现
→ 不重复弹出
```

通过以下方式去重：

- 术语标准化；
- 同义词合并；
- 缩写与全称合并；
- 单复数与不同说法归一化。

例：

```text
胃肠功能紊乱
胃肠道功能紊乱
肠胃功能失调
```

若语义一致，视为同一个概念。

---

### 12.2 首次出现不重要，后文才成为核心

首次只是顺带提到，不自动触发。

当后文第一次成为核心结论或前置概念时，再触发。

判断依据：

```text
首次出现位置
≠
首次值得解释的位置
```

## 13. 触发时间

### 13.1 离线预处理

本 Skill 应在视频播放前完成：

- 候选识别；
- 上下文检查；
- Top1 评分；
- 一句话解释生成；
- 触发时间生成。

播放时只按照时间轴发送事件，不临时让模型重新判断。

---

### 13.2 默认触发时间

```text
trigger_at_ms =
知识断层所在完整语义句结束时间
+ 300～800ms
```

前提：

- 后文没有立即解释；
- 当前处于自然停顿；
- 没有其他轻提示占用；
- 没有超过频率限制。

---

### 13.3 后文解释检查

检测到候选时，不立刻确定触发。

```text
发现候选
→ 检查后续 8～15 秒
→ 作者已解释
   → 取消
→ 作者未解释
   → 把触发点放在原句结束后的自然停顿
```

由于属于离线预处理，系统可以提前知道后文，因此无需真的延迟 8～15 秒再弹出。

---

## 14. 轻提示生成规则

### 14.1 标题

默认形式：

```text
{概念}是什么？
```

可适度去掉不必要前缀：

```text
胃肠功能紊乱是什么？
→ 功能紊乱是什么？
```

要求：

- 7～14 字优先；
- 用户一眼知道要解释什么；
- 不写成考试题；
- 不加入第二个概念；
- 不混入真假核验；
- 不混入抽象数据问题。

---

### 14.2 副标题

默认：

```text
一句话补懂
```

也可以根据概念类型使用：

```text
先补上这个前置知识
别把它理解成另一回事
```

要求：

- 6～14 字；
- 不提前写完整答案；
- 不制造恐慌；
- 不绝对化；
- 不引入新的术语。

---

### 14.3 一句话答案

结构：

```text
通俗定义
+ 必要边界
```

例：


要求：

- 20～45 字优先；
- 不使用更多专业术语；
- 不展开完整百科背景；
- 不加入与当前句无关的知识；
- 医疗、金融、安全内容保留必要边界。

## 19. 严格排除清单

以下内容不得由本 Skill 自动触发：

- 只有数字尺度感问题；
- 对视频结论真假的怀疑；
- 作者已经解释清楚的术语；
- 普通常识词；
- 与主线无关的机构、人物和地名；
- 仅仅因为词语长或看起来专业；
- ASR 识别不确定；
- 无法用一句话准确解释；
- 需要同时解释两个概念才能成立的问题；
- 纯粹适合画图，但不存在词义断层的内容；
- 为了增加卡片数量而强行抽取。

## 21. 最终规则

> 当视频文案中出现普通用户可能不懂、视频没有解释、并且会影响主线理解的概念时，将其视为知识断层候选。

> 当同一句出现多个候选时，分别按照“主线理解必要性、误解风险、用户陌生度、后续依赖程度、单次解释收益”五个维度评分，只选择总分最高且达到 70 分的一个概念触发。

> 其他候选不合并、不连续弹出、不在同一句中生成第二个轻提示。

## 22. 知识断层解释卡生成

除了输出轻提示与一句话解释外，当最终选出的知识断层**适合用“问题 + 回答 + 贴图”进一步解释**时，还应生成一张独立的**知识断层解释卡**。

这张卡的用途不是做真假验证，也不是做数字尺度对比，而是：

> 把用户“不懂这个词是什么意思”的问题，用一个更直观、更有记忆点的小卡片讲明白。

### 22.1 生成解释卡的前置条件

只有当以下全部满足时，才生成解释卡：

1. **已选出句内唯一 Top1 概念**  
   只能对当前句最终保留的那一个知识断层生成卡片，不允许两个候选一起生图。

2. **概念本身适合通俗化解释**  
   需要能把该概念转化成用户熟悉的话、拟人比喻、部件关系或简化场景。  
   如果只是机构名称、作者姓名、地名或不适合画面表达的背景信息，不强行生图。

3. **一张卡片能讲清核心意思**  
   一张卡只解释一个概念，不能同时扩展到多个相关概念、多个争议点、多个机制。

4. **贴图能明显降低理解成本**  
   视觉表达必须真的有帮助，比如：
   - 拟人化器官贴图；
   - “正常 vs 暂时失调”的状态对比；
   - 简化结构或工作流程；
   - 一眼能懂的生活类比。  
   如果只有纯文字更清楚，就不必生图。

5. **不会偏离原识别结果**  
   卡片中的问题、回答、贴图，都必须严格服务于最终选中的那个概念。

---

### 22.2 解释卡的固定结构

所有知识断层解释卡都必须采用统一结构：

#### 顶部问题区

顶部必须先直接提出当前概念问题：

```text
什么是“胃肠功能紊乱”？
什么是“2A类致癌物”？
什么叫“向上管理”？
```

要求：

- 问题必须由最终选中的概念直接生成；
- 语气像替用户发问；
- 不能混入第二个概念；
- 标题优先简洁直接，不绕弯。

#### 中部回答区

中部必须给出一句**短、直白、先给结论**的回答。

例如：

```text
不是胃坏了，是暂时工作不顺。
不是“接触就会致癌”，而是风险证据等级更高。
不是拍马屁，而是主动理解上级目标、提高协作效率。
```

要求：

- 先讲“它不是啥 / 它其实是啥”，帮助用户快速纠偏；
- 回答要比轻提示里的 one_line_answer 更口语、更有记忆点；
- 允许轻微拟人化，但不允许失真；
- 禁止学术腔、定义腔、论文腔。

#### 右侧或主视觉贴图区

回答区旁边必须有**主贴图**，用于强化理解。

贴图应根据概念动态生成，例如：

- **器官类概念**：拟人化胃、肠道、心脏、肺等；
- **分类概念**：风险牌、等级牌、标签牌、分层图标；
- **机制概念**：齿轮卡顿、运输堵塞、流程节奏乱掉；
- **工作/管理概念**：人物、箭头、上下关系、对话框；
- **历史制度概念**：人物身份、关系链、简化制度图示。

贴图原则：

- 简洁 2D 科普贴纸插画；
- 可以轻微 2.5D 体积感；
- 有清晰白色模切轮廓；
- 一眼能识别，不追求写实；
- 服务解释，不是装饰。

#### 底部补充说明区

卡片底部可补一小段更完整的通俗说明，用于把回答再讲稳一点。

例如：

```text
胃本身没坏，只是蠕动、消化、排空等“工作节奏”暂时乱了，所以会不舒服。
```

要求：

- 1～2 句；
- 帮助用户防止误解；
- 不重新引入大量新术语；
- 仍然服务于同一个概念。

---

### 22.3 解释卡与轻提示的关系

轻提示负责把用户“拉进来”，解释卡负责把概念“讲明白”。

对应关系：

```text
轻提示：
功能紊乱是什么？
一句话补懂

点击后展开解释卡：
什么是“胃功能紊乱”？
不是胃坏了，是暂时工作不顺～
[胃的拟人贴图]
胃本身没问题，但蠕动、消化、排空等“工作节奏”暂时乱了，就会出现不适。
```

规则：

1. 轻提示和解释卡的核心概念必须一致；
2. 解释卡是轻提示的展开内容，不可换题；
3. 解释卡比轻提示更直观，但不比详情页更长；
4. 解释卡优先解决“用户先看懂”的问题，再考虑美观。

---

### 22.4 解释卡输出字段

当满足解释卡生成条件时，除基础知识断层识别结果外，还需额外输出：

```json
{

  "explainer_card": {

      "一个粉色拟人化胃贴图",
      "一个点赞或提醒动作",
      "一个对话气泡承载核心答案",
      "底部一行通俗说明文字"
    ],

  }

```

字段要求：

- `question`：当前概念问题；
- `answer`：口语化短回答；
- `visual_strategy`：为什么这样画，主要帮助用户看懂什么；
- `visual_elements`：必须明确主要贴图元素；
- `layout_note`：说明整体版式。

### 22.5 解释卡生成 prompt 规则

当生成解释卡时，prompt 必须满足以下要求：

1. **必须明确卡片尺寸与比例**  
   生成一张宽 310px、高 180px、横向 31:18 比例的移动端短视频知识补充卡。

2. **必须明确固定结构**  
   卡片必须包含：
   - 顶部问题；
   - 中部回答；
   - 主贴图；
   - 底部补充说明。

3. **必须明确内容来源**  
   问题与回答必须来自最终选中的知识断层概念，不可换成别的相关知识点。

4. **必须明确画面风格统一**  
   优先使用：
   - 深黑或深蓝圆角卡片背景；
   - 简洁 2D 科普贴纸插画；
   - 轻微 2.5D 体积；
   - 粗白色模切外轮廓；
   - 高对比、移动端小尺寸可读。

5. **必须明确主贴图是什么**  
   不可只写“放一个插画”，必须明确：
   - 贴图主体；
   - 它的动作或状态；
   - 与回答的关系；
   - 是否需要对话气泡、符号或小图标辅助。

6. **必须保证一张卡只解释一个概念**  
   不允许同时解释“功能紊乱”和“胃黏膜损伤”的区别；  
   不允许把真假验证内容混进去；  
   不允许把抽象数字对比混进去。

7. **必须保证文字少而清楚**  
   小尺寸卡片下：
   - 标题短；
   - 回答短；
   - 底部说明控制在 1～2 句；
   - 禁止大段说明文字。

8. **必须体现“先纠偏，再解释”**  
   尤其是容易误解的概念，优先用：
   - “不是……，而是……”
   - “不等于……”
   - “更像是……”

9. **必须与概念类型匹配**
   - 器官 / 状态：拟人化器官或工作状态类比；
   - 分类 / 等级：标签牌、风险牌、分级图标；
   - 缩写 / 机构：机构身份 + 作用的简化表达；
   - 行业黑话：人物关系、流程或动作场景；
   - 历史制度：人物 + 身份关系 + 制度作用。

### 22.7 概念类型与贴图策略映射

#### mechanism_state（机制 / 状态类）

如：

#### classification_standard（分类 / 等级类）

贴图优先：

#### abbreviation_entity（缩写 / 机构类）

贴图优先：

- 人物关系；
- 箭头；

#### historical_cultural（历史制度类）

如：

- 荫封
- 察举制

贴图优先：

- 古代人物贴图；
- 身份标签；
- 制度路径或关系链。

### 22.8 不生成解释卡的情况

以下情况即使识别为知识断层，也不强行生成卡片：

1. 只是机构或地名，视觉解释价值很低；
2. 解释需要同时展开多个概念；
3. 当前概念无法在 310×180 小卡中讲清；
4. 一句话定义已经足够，不需要额外贴图；
5. 视觉化后容易误导用户；
6. 解释卡会偏离当前视频主线；
7. 当前概念与其他链路边界混淆，实际上更适合走抽象数据或说法验证。

## 24. 解释卡版式强约束（更新版）

对知识断层解释卡，版式必须进一步收紧。不要自由发挥成多段问答卡、多贴纸卡、多说明卡。

### 24.1 固定结构

每一张知识断层解释卡都必须严格采用以下结构：

```text
顶部：问题
中部：一个贴纸 + 一个回答
```

只允许这两个核心层级，必要时可在底部加极短补充说明，但不是必须项。

---

### 24.2 顶部必须是问题

卡片顶部必须直接显示问题，且问题必须由当前提取识别到的概念生成。

正确示例：

- 什么是“胃肠功能紊乱”？
- 什么叫“向上管理”？
- 什么是“2A类致癌物”？

要求：

1. 顶部一定是问题，不允许改成陈述句标题；
2. 问题必须直接围绕当前选中的概念；
3. 不允许把两个概念写进同一个问题；
4. 不允许把真假判断、数字对比混进来；
5. 标题要像用户会问的话，而不是学术标题。

错误示例：

- 胃肠功能紊乱解释
- 关于2A类致癌物
- 冰水伤胃是真的吗
- 65℃到底有多烫

其中最后两项分别属于说法验证、抽象直观化，不属于知识断层解释卡。

---

### 24.3 中部必须是“一个贴纸 + 一个回答”

卡片中部必须只包含：

- **一个主贴纸**
- **一个主回答**

不允许：

- 两个贴纸并列
- 多个回答气泡
- 左边解释、右边再解释一段
- 上下堆多个视觉主体

#### 回答要求

回答必须是当前概念的核心解释，短、直、好懂。

优先结构：

```text
不是……，而是……
不等于……，更像是……
就是……
```

示例：

- 不是胃坏了，是暂时工作不顺。
- 不是“接触就会致癌”，而是风险证据等级更高。
- 不是拍马屁，而是主动理解上级目标。

要求：

1. 回答必须只有一个核心句；
2. 回答必须直接解释当前概念；
3. 回答要口语化、记忆点强；
4. 回答不得引出第二个核心问题。

#### 贴纸要求

贴纸必须符合当前提取识别到的内容，不能为了好看随便放一个泛用装饰图。

也就是说：

> 贴纸不是“通用可爱元素”，而是“当前概念的视觉化表达”。

例如：

- 提取内容是 **胃肠功能紊乱**  
  → 贴纸应是拟人化胃 / 肠道 / “工作节奏乱了”的胃，不应是通用医生、问号、灯泡。

- 提取内容是 **2A类致癌物**  
  → 贴纸应是分级牌、标签牌、风险等级视觉，不应是一个泛用卡通人。

- 提取内容是 **向上管理**  
  → 贴纸应体现人与上级、沟通、目标对齐，不应是随机办公桌。

- 提取内容是 **荫封**  
  → 贴纸应体现古代人物、身份继承、制度关系，不应是现代职场人物。

贴纸要求：

1. 只能有一个主贴纸；
2. 贴纸必须与当前概念直接对应；
3. 贴纸要帮助理解，而不是装饰；
4. 优先用拟人化、关系化、标签化、结构化方式表达概念；
5. 贴纸必须适合小尺寸卡片，一眼可识别。

### 24.5 prompt 规则更新

生成解释卡 prompt 时，必须明确写出以下硬约束：

1. 顶部必须是问题；
2. 中部必须只有一个贴纸和一个回答；
3. 贴纸必须符合提取识别到的内容；
4. 回答必须直接解释提取识别到的概念；
5. 卡片不能偏成“装饰海报”；
6. 卡片不能出现多个贴纸主体；
7. 卡片不能把问题、回答、贴纸分散成复杂结构。

```text
3. 贴纸必须符合当前提取识别到的内容，不能使用泛用装饰图
4. 回答必须直接解释该概念，显示：【main_answer】
5. 如有底部补充说明，只能用1到2句极短说明，显示：【optional_bottom_note】

```

> 如果无法生成一个与当前概念强相关的主贴纸，则宁可不生成解释卡，也不要用不相关的贴纸凑数。

## 25. 卡片尺寸固定为 310×180

知识断层解释卡的画布尺寸必须永久锁定为：

```text
宽度：310px
高度：180px
方向：横向
宽高比：31:18
```

这是固定产品规格，不是建议值，也不是可选项。

### 25.1 原生尺寸构图

必须按 310×180 原生小尺寸直接构图，不允许：

- 先按 16:9 大图构图后再缩小；
- 先生成 1920×1080 海报再裁切；
- 使用接近比例代替 310×180；
- 自动扩展画布；
- 增加手机外框、展示背景或额外留白；
- 改成正方形、竖版或其他横版比例。

固定字段：

```json
{
  "canvas": {
    "width_px": 310,
    "height_px": 180,
    "aspect_ratio": "31:18",
    "orientation": "landscape",
    "native_size_required": true,
    "locked": true
  }
}
```

---

### 25.2 固定安全边距

卡片四周必须保留约 10px 安全边距。

```json
{
  "safe_margin_px": 10
}
```

所有关键内容必须放在安全区域内：

- 顶部问题；
- 中部回答；
- 主贴纸；
- 可选底部补充说明。

不得贴边、裁切或越出圆角区域。

---

### 25.3 310×180 下的内容密度限制

因为画布很小，必须控制内容：

- 顶部只放一个问题；
- 中部只放一个主贴纸；
- 中部只放一个主回答；
- 底部补充说明最多 1～2 句；
- 禁止第二个贴纸；
- 禁止第二个回答块；
- 禁止额外标签、栏目名、来源角标；
- 禁止复杂背景或大量装饰。

推荐结构：

```text
顶部问题区：约占高度 26%～30%
中部贴纸 + 回答区：约占高度 55%～62%
底部补充说明区：约占高度 12%～18%
```

参考范围：

```text
顶部问题区：y = 10px ～ 50px
中部主体区：y = 52px ～ 145px
底部说明区：y = 147px ～ 170px
```

如果底部说明导致拥挤，应优先删除底部说明，不得缩小顶部问题和主回答硬塞内容。

---

### 25.4 小尺寸文字限制

#### 顶部问题

- 单行优先；
- 建议不超过 14 个汉字；
- 极限不超过 18 个汉字；
- 白色粗体；
- 在 310×180 原尺寸下清晰可读。

#### 主回答

- 1～2 行；
- 建议不超过 22 个汉字；
- 极限不超过 30 个汉字；
- 必须是唯一核心解释。

#### 底部说明

- 最多 1～2 句；
- 建议不超过 32 个汉字；
- 如影响可读性则删除。

---

### 25.5 小尺寸贴纸限制

主贴纸必须：

- 只有一个视觉主体；
- 占画面主体区约 35%～45%；
- 轮廓简洁；
- 细节不能过多；
- 必须与提取内容直接对应；
- 在 310×180 下仍能一眼识别。

不得：

- 贴纸过大遮住问题或回答；
- 贴纸过小失去意义；
- 使用复杂多人场景；
- 使用多个小贴纸凑成一组；
- 使用无关装饰贴纸。

---

### 25.6 Prompt 必须重复写明尺寸

每次生成解释卡 Prompt 时，开头必须明确写：

```text
生成一张严格为310px×180px的横向移动端知识断层解释卡，横向比例固定为31:18，必须按310×180原生小尺寸构图。
```

结尾必须再次强调：

```text
最终输出尺寸必须严格为310×180px，不得改为其他比例，不得增加外部留白、手机外框或展示场景。
```

这样做是为了防止模型自作主张把卡片升级成一张“更有发挥空间”的大海报。它当然很有创造力，问题是产品不需要它在这里追梦。

### 25.7 更新后的最终卡片硬规则

> 所有知识断层解释卡必须严格输出为 310×180px、31:18 横向比例，并按原生小尺寸构图。

> 顶部必须是问题；中部必须只有一个主贴纸和一个主回答；贴纸必须符合当前提取识别内容。

> 当文字、贴纸和补充说明无法同时在 310×180 中清晰呈现时，优先保留“问题 + 贴纸 + 回答”，删除底部补充说明，不得缩小到难以阅读。

## 26. 视觉语义映射与图片审核（最高优先级）

本节解决一个核心问题：

> 提取内容正确，但贴纸只画了“相关对象”，没有表达概念真正的状态、关系或含义，甚至与回答相反。

例如：

```text
提取：胃肠功能紊乱
错误贴纸：开心、竖大拇指的胃
```

主体虽然是胃，但视觉表达“状态很好”，与“功能暂时失调”相反，必须判定为不合格。

若本节与前文冲突，以本节为准。

### 26.1 禁止从概念直接跳到生图

必须执行：

```text
selected_term
→ 核心定义
→ 用户误解
→ 视觉表达类型
→ 主体
→ 状态或关系
→ must_show
→ must_not_show
→ 生成Prompt
→ 生图
→ 语义审核
```

无法生成完整视觉语义计划时：

```yaml
generate_explainer_card: false
reason: visual_semantics_unclear
```

## 27. 视觉语义计划

每张解释卡生成前必须输出：

```json
{
  "visual_semantic_plan": {
    "selected_term": "胃肠功能紊乱",
    "core_definition": "胃肠结构未必受损，但蠕动、消化、排空等功能节奏暂时失调",
    "user_misconception": "用户可能以为胃已经被损坏",
    "visual_type": "subject_state",
    "sticker_subject": "拟人化胃",
    "must_express": "胃本身完整，但工作节奏暂时混乱",
    "must_show": [
      "完整无破损的胃",
      "轻微困惑或不适表情",
      "不同步、错位或卡顿的运动符号"
    ],
    "must_not_show": [
      "开心竖大拇指",
      "完全健康顺畅的状态",
      "破裂、流血或腐烂"
    ],
    "semantic_link_to_answer": "贴纸必须表现“不是胃坏了，而是暂时工作不顺”"
  }

```

## 28. 贴纸必须匹配三层语义

贴纸必须同时匹配：

1. **概念主体**：在讲谁或什么；
2. **核心状态或关系**：主体发生了什么；
3. **主回答含义**：贴纸与回答是否表达同一件事。

只满足第一层，不合格。

### 合格示例

```text
问题：什么是“胃肠功能紊乱”？
回答：不是胃坏了，是暂时工作不顺。
贴纸：完整无破损的胃，轻微困惑，周围运动箭头不同步。
```

### 不合格示例

```text
贴纸：开心竖大拇指的胃。
```

原因：

```text
主体正确，但状态与回答相反。
```

## 29. 视觉表达类型

生成贴纸前必须选择一种 `visual_type`。

### A. 主体状态型 `subject_state`

适用：

- 器官状态；
- 身体反应；
- 心理状态；
- 对象处于异常或特殊状态。

结构：

```text
主体 + 状态 + 必要符号
```

### B. 关系型 `relationship`

适用：

- 上下级关系；
- 人物关系；
- 权利关系；
- 信息流向。

结构：

```text
核心人物或对象 + 关系箭头 + 目标对象
```

卡片仍只能有一个视觉中心，不得拆成多个分散贴纸。

### C. 分类标签型 `classification_label`

适用：

- 风险等级；
- 分类标准；
- 证据等级；
- 响应等级。

结构：

```text
主标签牌 + 等级提示 + 必要边界
```

### D. 流程动作型 `process_action`

适用：

- 做空；
- 冷启动；
- 去杠杆；
- 反馈循环。

结构：

```text
核心对象 + 关键动作 + 明确结果
```

### E. 身份制度型 `identity_system`

适用：

- 荫封；
- 察举制；
- 门阀；
- 摄政。

结构：

```text
核心人物或身份符号 + 制度路径 + 获得的资格或权力
```

### F. 机构身份型 `entity_identity`

适用：

- IARC；
- WHO；
- 其他确实影响主线的机构或缩写。

结构：

```text
它是谁 + 它负责什么
```

机构本身不影响主线时，不生成解释卡。

## 30. 主贴纸生成硬规则

### 30.1 主贴纸必须承担解释任务

禁止使用：

- 通用问号；
- 通用灯泡；
- 随机医生；
- 随机人物；
- 可爱小动物；
- 只为填空的装饰图。

判断：

> 去掉文字后，贴纸是否仍能大致表达该概念的核心状态或关系？

完全不能，则贴纸不合格。

### 30.2 `main_sticker` 必须写清四项

```text
主体
+ 状态
+ 动作或符号
+ 要表达的概念含义
```

错误：

```text
一个胃贴纸
```

正确：

```text
一个完整无破损的拟人化粉色胃贴纸，
表情轻微困惑，
周围有方向不同的运动箭头和轻微卡顿符号，
表达胃肠工作节奏暂时失调。
```

### 30.3 `must_show`

每张卡至少2项，必须包含：

- 核心主体；
- 核心状态或关系。

### 30.4 `must_not_show`

每张卡至少2项，必须包含：

- 与概念相反的状态；
- 会造成新误解的视觉。

医疗、金融、安全内容还必须禁止：

- 恐怖化；
- 绝对化；
- 结果夸张；
- 把不确定内容画成确定事实。

---

## 31. 固定卡片结构不变

所有知识断层解释卡继续严格锁定：

```text
尺寸：310×180px
比例：31:18
方向：横向
构图：310×180原生小尺寸
安全边距：约10px
```

固定结构：

```text
顶部：一个问题
中部：一个主贴纸 + 一个主回答
底部：可选极短说明
```

视觉语义计划只决定贴纸画什么、处于什么状态、表达什么关系，不得改变卡片结构。

## 34. 生图后的视觉语义审核

图片生成后不得直接交付，必须审核：

1. 主体是否匹配提取概念；
2. 状态或关系是否匹配核心定义；
3. 贴纸是否匹配主回答；
4. 是否出现与回答相反的视觉；
5. 是否引入新的误解；
6. 是否只有一个主贴纸；
7. 顶部是否仍是问题；
8. 是否严格为310×180。

评分：

```text
final_score =
0.25 × 主体匹配
+ 0.30 × 状态或关系匹配
+ 0.25 × 回答匹配
+ 0.20 × 版式合规
- 误导风险
```

通过门槛：

```yaml
final_score >= 0.82:
  passed: true

final_score < 0.82:
  passed: false
  action: regenerate
```

以下情况无论总分多少，强制重生：

- 出现 `must_not_show` 元素；
- 贴纸表达与回答相反；
- 只画主体，没有表达状态或关系；
- 主贴纸与概念无直接关系；
- 出现多个主贴纸；
- 顶部不是问题；
- 不是310×180。

审核失败示例：

```json
{
  "visual_semantic_audit": {
    "passed": false,
    "conflict_reason": "胃开心竖大拇指，表达健康顺畅，与功能暂时失调相反",
    "regenerate_instruction": "保留完整无破损的胃，改为轻微困惑表情，增加不同步运动箭头，删除点赞动作"
  }
}
```

## 35. 典型错误与修正

### 胃肠功能紊乱

错误：

```text
一个可爱的胃。
```

修正：

```text
完整无破损的胃 + 轻微困惑 + 不同步运动箭头。
```

### 2A类致癌物

错误：

```text
恐怖致癌怪物。
```

修正：

```text
2A等级标签牌 + 证据等级提示，不表现必然致癌。
```

### 向上管理

错误：

```text
一个人在办公室工作。
```

修正：

```text
下属主动向上汇报，用目标卡片和箭头与上级对齐。
```

### 荫封

错误：

```text
一个普通古代人物。
```

修正：

```text
古代人物通过父辈身份关系获得入仕资格，突出身份继承路径。
```
