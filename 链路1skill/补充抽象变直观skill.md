# 科普视频抽象数据直观化识别 Skill v13：原子候选与解释证据锁定版

## 1. Skill 定位

本 Skill **只识别视频中的抽象数据**，不识别普通抽象概念、机制、原理、因果过程或专业名词。

核心任务：

> 从视频字幕、OCR 和上下文中，找出“用户听到数字，但难以形成现实尺度感，并可能自然产生‘这到底是什么概念’好奇”的数据，再生成统一风格的直观化方案与生图提示词。

本 Skill 不负责：

- 普通知识断层解释；
- 抽象机制可视化；
- 专业名词解释；
- 视频说法真伪核验；
- 视频内容总结；
- 行动建议；
- 为了好看而强行选题。

**本 Skill 必须同时读取字幕与视频画面。仅依赖字幕判断是否已直观化是不合格的。**

只要作者已经通过以下任一方式把数据讲具体，就不得再次提取：

- 真实物体模拟；
- 画面比例对照；
- 物体堆叠；
- 数量动画；
- 熟悉场景对比；
- 数值刻度或区间；
- 口播中的生活化参照；
- 画面与口播共同完成的解释。

---

## 2. 抽象数据的严格定义

候选必须同时满足以下条件：

1. 原文中出现**明确数字或数量级**；
2. 数字与单位、比例、倍数、概率、阈值或数量关系绑定；
3. 普通用户仅凭数字难以形成现实感受；
4. 用户可能自然追问：
   - “这到底有多大？”
   - “这到底有多快？”
   - “这到底有多热？”
   - “这到底有多重？”
   - “这到底有多危险？”
   - “这个概率到底意味着什么？”
5. 视频当前知识点尚未用参照物、场景、例子、对比或图示讲直观；
6. 可以通过熟悉参照、尺度阶梯、区间分档或现实结果在 3～5 秒内讲清楚。

只有全部满足，才可提取。

### 2.1 候选不是按单句判断，而是按“解释闭环”判断

同一个数据常常先被提出，后面才用一到数句完成直观化。

因此不得采用：

```text
发现数字
→ 只看当前句
→ 立即提取
```

必须采用：

```text
发现数字
→ 建立数据候选
→ 继续追踪同一数据的后续指代与解释
→ 等解释闭环结束
→ 再判断是否仍然抽象
```

如果后文通过“它、这个数字、这些钱、这笔钱、这样的规模、前者、后者”等词继续解释同一个数据，必须合并为一个知识点，不得把后文误判为新话题。

### 2.2 不只判断“作者有没有处理”，还要判断“处理到了哪里”

旧规则：

```text
作者做过换算
→ 全部抑制
```

会导致两类错误：

1. 作者只是把一个抽象概念换成另一个抽象概念；
2. 作者使用了跨领域类比，但类比对象本身仍然让用户没有概念。

新版必须判断解释链的终点：

```text
原始表达
→ 作者换算或类比
→ 解释终点
→ 判断终点是否真正解决尺度感
```

最终分为三种状态：

```text
full_resolution
partial_resolution
no_resolution
```

#### A. 完全解决 `full_resolution`

满足任一条件：

- 落到用户熟悉的现实参照；
- 落到明确可感知的体感、时间、空间或数量；
- 通过画面真实模拟；
- 转换为目标用户熟悉的本地货币或常用单位，且作者明显是在做受众本地化；
- 引用了视频前文已经完成直观化的数据对象。

处理：

```text
整个数据簇抑制
```

#### B. 部分解决 `partial_resolution`

作者进行了换算或类比，但解释终点本身仍然抽象。

处理：

```text
原始数据不重复提取
→ 只评估解释链终点
→ 终点满足抽象数据条件时，提取终点
```

#### C. 未解决 `no_resolution`

作者没有给出任何有效解释。

处理：

```text
评估原始数据
```

核心原则：

> 作者的解释已经解决哪一层，就不重复哪一层；仍然没解决的最后一层，才可能成为候选。

### 2.3 候选必须是“原文原子数据”，不能是模型总结

候选的 `source_span` 必须满足：

1. 来自原文连续片段；
2. 逐字一致，不改写；
3. 只包含一个核心数据对象；
4. 不把作者后文的解释、参照和结果拼进候选；
5. 不生成“概括性标题”冒充原文关键词。

允许：

```text
超过3000万亿元
214万元
800伏
```

禁止：

```text
全球金融资产超3000万亿元
3000万亿资产平分中国人，人均214万元，纸币铺满网球场
马斯克万亿级股票资产可铺满纽约市
马斯克巅峰身家八九千亿美元、突破万亿美元
```

上述禁止项的问题是：

- 不是原文连续片段；
- 合并了多个句子；
- 将数据、解释和画面结果揉成一个新命题；
- 模型自己替作者写了摘要。

生成的问题标题放入 `natural_question`，不能写进 `source_span`。

必须输出：

```json
{
  "source_span": "超过3000万亿元",
  "span_verbatim": true,
  "span_start_char": 0,
  "span_end_char": 9
}
```

`span_verbatim = false` 时，该候选直接作废。

### 2.4 先给数字标注角色，再决定是否提取

同一解释闭环中的数字必须先分角色：

```text
source_data
author_translation
concrete_reference
comparison_baseline
change_endpoint
real_world_outcome
background_context
unresolved_candidate
```

只有 `unresolved_candidate` 可以进入 `selected_candidates`。

其他角色的用途：

- `source_data`：等待作者后续是否解释；
- `author_translation`：作者的换算结果；
- `concrete_reference`：作者用来直观化的参照；
- `comparison_baseline`：比较基准；
- `change_endpoint`：变化前后值；
- `real_world_outcome`：破产、铺满、盖住等结果；
- `background_context`：仅用于叙事背景。

以下内容绝不能被当作新候选：

```text
作者用来解释前一个数字的数字
作者用来对比的国家GDP
作者给出的平均分配结果
作者给出的铺满、盖住、垒高结果
变化事件中的起点和终点组合
```

### 2.5 一个现实对象只建立一个“数据解释簇”

必须按以下键聚合同一事实：

```text
实体 + 指标 + 时间范围 + 语义目标
```

示例：

```text
实体：全球金融资产
指标：总规模
时间范围：当前
语义目标：有多少
```

该簇内包括：

```text
超过3000万亿元
比广义货币多两倍
平均给中国人每人214万元
铺满网球场
```

这些不是四个候选，而是同一个解释簇。

只要簇内出现一个有效直观化终点：

```text
cluster_resolution_status = full_resolution
→ 整个簇不得进入 selected_candidates
```

### 2.6 解释证据不能反过来成为候选

当一句话的作用是回答前文数字“有多大、多少、多久、什么概念”时，该句属于解释证据。

典型结构：

```text
原始数据
→ 平均分给……
→ 每人……
→ 能铺满……
```

此时：

- 原始数据被抑制；
- 平均结果被抑制；
- 铺满结果作为证据保存；
- 不得重新组合成一个更长候选。

例如：

> “超过3000万亿元。如果平均分给每个中国人，每人能拿到214万元，刚好能够平铺满一整个网球场。”

必须输出：

```text
selected_candidates = []
```

不得输出：

```text
3000万亿资产平分中国人，人均214万元，纸币铺满网球场
```

### 2.7 变化事件不是默认的抽象尺度候选

以下结构主要表达“变化事件”，不一定表达用户想追问的尺度：

```text
从A缩水到B
从A增长到B
翻了N倍
下降了N%
最终破产
```

若作者已经给出：

- 起点；
- 终点；
- 变化方向；
- 现实后果；

则用户已经能理解事件严重性，默认不提取。

例：

> “雷曼兄弟市值从300多亿美元缩水到几十亿，最终宣布破产。”

处理：

```text
role = change_event
resolution_status = full_resolution
trigger_level = suppress
```

只有同时满足以下条件时，变化数据才可进入评分：

1. 变化幅度本身是视频核心；
2. 用户仍然无法理解其尺度；
3. 作者没有给出现实后果或熟悉参照；
4. 用户好奇度达到阈值；
5. 可以用一个核心数字准确直观化。

### 2.8 全部已经解释时，空结果是正确答案

本 Skill 不要求每个视频都必须提取内容。

如果所有数字都属于：

- 作者已经直观化；
- 作者已经换算；
- 作者已经比较；
- 解释证据；
- 变化事件；
- 普通生活数据；

必须输出：

```json
{
  "selected_candidates": []
}
```

不得为了证明 Skill 有工作而制造候选。毕竟产品不是按每分钟弹窗数量发奖金。

## 3. 允许提取的数据类型

### 3.1 温度

示例：

- 65℃
- 零下 196℃
- 核心温度升高 1℃

用户缺少：

- 体感；
- 所处区间；
- 超过阈值后的现实结果。

### 3.2 电压、电流、功率与能量

示例：

- 800V
- 10万伏
- 1000焦耳
- 2兆瓦

用户缺少：

- 与日常用电的差距；
- 数量级；
- 安全意义；
- 能量或功率对应的现实结果。

注意：

> 电压不能单独直接等同于伤害或痛感。涉及“800伏有多痛”等表达时，本 Skill 只解释“800伏是什么电压尺度”；原说法是否成立，应交给“视频说法验证”链路。

### 3.3 长度、高度、距离、面积与体积

示例：

- 8848.86米
- 1光年
- 10万平方公里
- 3亿立方米

用户缺少：

- 空间尺度；
- 与生活尺度的层级关系。

### 3.4 速度与加速度

示例：

- 每秒30万公里
- 0到100公里加速2秒
- 20倍音速

用户缺少：

- 单位时间内能跨越多远；
- 与熟悉交通或运动速度的差距。

### 3.5 时间跨度与时间精度

示例：

- 0.01秒
- 1亿年
- 每10亿分之一秒

用户缺少：

- 极短或极长时间与日常时间的差距。

普通时间不提取：

- 10分钟；
- 2小时；
- 3天；

除非它是关键阈值且用户仍难感知。

### 3.6 质量、重量、密度与压力

示例：

- 1000亿个太阳质量
- 每平方厘米承受1000公斤
- 密度是水的20倍

用户缺少：

- 重量或压力的现实结果；
- 数量级差距。

### 3.7 概率、风险、比例与百分比

示例：

- 风险增加20%
- 万分之一
- 成功率0.01%
- 浓度达到5%

用户缺少：

- 绝对人数；
- 事件频率；
- 基线；
- 从比例到现实结果的映射。

没有基线时，不得擅自画人数图。

### 3.8 极大或极小数量

示例：

- 1000亿个
- 10的负9次方
- 300万倍

用户缺少：

- 数量级；
- 与熟悉单位的层级关系。

### 3.9 关键阈值

示例：

- 超过65℃
- 血氧低于90%
- 风速达到12级

用户缺少：

- 阈值前后意味着什么；
- 从“普通”到“异常”的变化。

## 4. 严格排除

以下内容不得提取。

### 4.1 没有明确数字的数据感词

- 微量
- 大量
- 很快
- 很久
- 巨大
- 极高
- 极低
- 长期
- 短暂

它们可以属于其他解释链路，但不属于本 Skill。

### 4.2 普通抽象机制或原理

- 膳食纤维控糖机制
- 咖啡因阻断腺苷受体
- 胃肠功能紊乱
- 反馈循环
- 多巴胺释放

即使适合画图，也不得由本 Skill 提取。

### 4.3 专业名词

- 2A类致癌物
- 腺苷受体
- 功能紊乱
- 板块俯冲

它们属于知识断层解释，不属于抽象数据直观化。

### 4.4 熟悉生活数据

- 一天不到10元
- 体重六七十公斤
- 两杯水
- 30分钟
- 三个人
- 五个步骤

普通用户已有稳定经验，不需要再次直观化。

### 4.5 已经具体化的数据

原文：

> “65℃相当于明显烫口的热饮温度。”

不得再次提取。

原文：

> “珠峰约等于9个1千米高度。”

不得再次提取。

### 4.6 已经是生活对比的表达

- 10元干净饮食对比高油外卖
- 一杯奶茶相当于几碗饭
- 88栋楼叠起来

作者已经完成直观化，不再生成第二套对比。

### 4.7 作者已完全解决的数据

以下情况直接排除：

- 已落到熟悉现实参照；
- 已用画面真实模拟；
- 已完成目标用户的本地货币或常用单位转换；
- 已引用前文完成直观化的数据对象；
- 解释链终点评分达到 `0.75`。

作者只是把抽象内容换成另一个仍然抽象的内容时，不得直接排除，应按“部分解决”规则评估解释终点。

### 4.8 仅适合做图但不抽象

“能画出来”不是提取理由。

如果用户不看图也能直接理解该数字，必须排除。

## 5. 作者已直观化时禁止触发

### 5.1 判断原则

识别到抽象数据后，不得立即提取。

必须先判断：

> 作者是否已经在同一知识点中，通过字幕、口播、画面或二者结合，让用户形成了直观尺度感？

只要答案是“是”，候选必须取消。

```text
发现抽象数据
→ 暂存候选
→ 等待当前知识点讲完
→ 检查字幕中的具体化表达
→ 检查同期画面是否已经展示
→ 检查画面与数据是否语义对应
→ 已直观化：取消
→ 未直观化：进入评分
```

---

### 5.2 跨句指代与解释闭环识别

抽象数据是否已被直观化，不能只检查包含数字的原句，还必须追踪后续句子是否在继续解释它。

#### 5.2.1 必须识别的指代词

以下表达通常指向前文数据：

```text
它
这个数字
这个数
这些钱
这笔钱
这部分钱
这样的规模
这么多钱
前者
后者
上述金额
这一数量
这相当于
那放在现实里
换算下来
按照这个规模
```

还应识别省略主语的连续解释：

```text
能装满……
能堆成……
能铺满……
相当于……
大约是……
比……还……
需要……才能……
```

即使后句没有重复数字，也可能仍在解释前文数据。

#### 5.2.2 指代解析要求

对每个候选数据，建立：

```json
{
  "data_entity": "全球实体现金总量",
  "value": "55万亿元",
  "mentions": [
    "55万亿元实体的钱",
    "它",
    "这个数字"
  ],
  "explanation_span": "从首次出现到最后一个对应参照结束"
}
```

当后句中的代词满足以下条件时，应链接到候选数据：

1. 数量、对象和语义类别一致；
2. 中间没有出现更合适的新指代对象；
3. 后句在回答“多大、多高、多久、多少、什么概念”；
4. 后句给出了容量、长度、时间、数量或现实结果参照。

#### 5.2.3 解释闭环开始信号

以下表达意味着作者即将解释前文数据，候选必须继续等待：

```text
那放在现实里是什么概念呢
这是什么概念
到底有多少
到底有多大
到底有多高
换算成现实尺度
如果放在现实中
你可能没概念
更直观地说
举个例子
换句话说
也就是说
```

出现这些句子后，禁止在问题句结束处提前触发。

#### 5.2.4 解释闭环结束信号

满足以下任一条件，才允许结束等待：

- 已给出一个明确现实参照；
- 已给出一个完整尺度阶梯；
- 已完成“数据 → 参照 → 现实结论”；
- 话题明显切换到新概念；
- 出现新的独立知识点；
- 超过后续15秒仍没有解释。

如果作者先给出一个参照，后面又追加第二个参照，只要仍属于同一数据，就全部合并后再判断。

#### 5.2.5 强制抑制规则

只要同一解释闭环中存在一个有效直观参照：

```text
same_data_reference_found = true
→ already_concretized = true
→ suppress
```

不要求作者重复原数字。

例如：

> “全世界现在一共拥有55万亿元实体的钱。那放在现实里是什么概念呢？它能垒成和东方明珠差不多高的纸币大楼。”

解析：

```json
{
  "data_entity": "全球实体现金总量",
  "source_span": "55万亿元",
  "coreference_found": true,
  "coreference_expression": "它",
  "explanation_intent_found": true,
  "explanation_intent": "那放在现实里是什么概念呢",
  "concretization_expression": "垒成和东方明珠差不多高的纸币大楼",
  "already_concretized": true,
  "trigger_level": "suppress"
}
```

不得因为“东方明珠的具体高度没有写出”而重新提取。作者已经完成了视觉尺度对比，是否足够精确属于质量或求真问题，不属于本 Skill。

### 5.3 解释链分类、终点评估与部分解决

发现“相当于、约合、折合、换算成”等表达时，不能一律抑制。必须先分类作者做了哪一种解释。

#### 5.3.1 建立解释链

```json
{
  "data_entity": "被解释的事实",
  "explanation_chain": [
    {
      "value_text": "原始表达",
      "role": "source"
    },
    {
      "value_text": "作者给出的换算或类比",
      "role": "endpoint"
    }
  ]
}
```

同一个事实只能建立一个解释链，不能把链中每个数字分别生成候选。

---

#### 5.3.2 作者解释类型

##### 类型A：受众本地化换算 `audience_localization`

包括：

- 美元换成人民币；
- 华氏度换成摄氏度；
- 英里换成公里；
- 过去金额按今天购买力换算；
- 国外单位换成目标用户常用单位。

例：

```text
10万亿美元
→ 按今天购买力
→ 超过100万亿人民币
```

默认处理：

```text
full_resolution
→ 整个数据簇抑制
```

原因不是“100万亿已经很直观”，而是作者已经明确完成受众本地化。本产品默认不在作者刚做完本地化后再插入一张解释卡。

---

##### 类型B：生活化现实参照 `concrete_reference`

包括：

- 足球场；
- 运钞车；
- 一层楼；
- 人的身高；
- 每天花多少钱要花多久；
- 真实物体模拟；
- 视频前文已解释过的对象。

处理：

```text
full_resolution
→ 整个数据簇抑制
```

例：

```text
55万亿元
→ 55万辆运钞车
→ 东方明珠高度
```

---

##### 类型C：标准单位尺度换算 `scale_conversion`

包括：

- 光年换成公里；
- 米换成千米；
- 秒换成年；
- 科学计数法展开；
- 百分比换成人数。

必须判断换算终点是否真的更直观。

例1：

```text
0.01%
→ 每1万人约1人
```

终点可直观：

```text
full_resolution
→ suppress
```

例2：

```text
1光年
→ 9.46万亿公里
```

终点仍然抽象：

```text
partial_resolution
→ 只评估“9.46万亿公里”
```

如果原始表达比终点更适合用户理解，也可以保留原始数据，但只能选一个，不得同时提取。

---

##### 类型D：跨领域类比 `cross_domain_analogy`

包括：

- 痛感相当于800伏电击；
- 压力相当于多少头大象；
- 速度像子弹一样快；
- 能量相当于多少吨炸药。

跨领域类比不能自动视为完成直观化，必须检查类比终点。

例：

```text
子弹蚁咬一下的痛感
→ 相当于800伏电一下
```

“800伏”本身仍然抽象，且电压不能单独代表痛感。

正确处理：

```text
resolution_status = partial_resolution
candidate = 800伏
requires_claim_verification = true
```

直观化只解释：

> 800伏属于什么电压尺度？

不得在生图中重复或强化：

> 800伏等于子弹蚁痛感。

如果类比终点是用户熟悉对象：

```text
长度相当于两个足球场
```

则：

```text
full_resolution
→ suppress
```

---

##### 类型E：重复或同义重述 `mere_restatement`

例：

```text
损失10万亿美元
→ 也就是整整10万亿美元
```

没有增加任何解释。

处理：

```text
no_resolution
→ 继续评估原始数据
```

---

#### 5.3.3 解释终点评分

对解释链最后一个节点计算：

```text
endpoint_resolution_score =
0.30 × 日常熟悉度
+ 0.25 × 现实可感知程度
+ 0.20 × 是否降低数量级理解难度
+ 0.15 × 与原数据的语义准确度
+ 0.10 × 是否能在3～5秒内直接理解
- 二次抽象风险
- 科学误导风险
```

判定：

- `≥0.75`：`full_resolution`，抑制整个数据簇；
- `0.45～0.75`：`partial_resolution`，只评估终点；
- `<0.45`：`no_resolution`，评估原始数据或终点中更合适的一个。

例外：

```text
translation_type = audience_localization
```

即使终点仍是大数字，也默认视为 `full_resolution`，除非产品配置显式允许再次解释。

---

#### 5.3.4 只提取“最后未解决节点”

解释链：

```text
A → B → C
```

处理规则：

- C 已直观：全部抑制；
- C 仍抽象：只评估 C；
- B 抽象但 C 已直观：B 不提取；
- A、B、C 都抽象：选好奇度最高且最接近作者表达重点的一个；
- 一条链最多输出一个候选。

禁止：

```text
同时提取A和B
同时提取原始值和换算值
重新解释已经解决的中间节点
```

---

#### 5.3.5 引用前文已直观化对象

后文可能使用前文已经解释过的数据作为参照。

例：

```text
10万亿美元
→ 100万亿人民币
→ 相当于当下现金的两倍
```

如果“当下现金”在前文已经通过运钞车或东方明珠完成直观化：

```text
referenced_context_already_concretized = true
resolution_status = full_resolution
```

必须抑制整条链。

系统需要保存视频级上下文记忆：

```json
{
  "concretized_entities": [
    {
      "entity": "全球实体现金",
      "evidence": "55万辆运钞车、东方明珠高度"
    }
  ]
}
```

#### 5.3.6 精确案例一：购买力换算

输入：

> “全球股市蒸发了约10万亿美元。按照今天的购买力算，相当于超过100万亿人民币。”

解析：

```json
{
  "data_entity": "全球股市蒸发额",
  "translation_type": "audience_localization",
  "source_value": "约10万亿美元",
  "endpoint_value": "超过100万亿人民币",
  "resolution_status": "full_resolution",
  "cluster_suppressed": true
}
```

结果：

```text
不提取10万亿美元
不另建100万亿人民币候选
```

---

#### 5.3.7 精确案例二：抽象类比终点

输入：

> “子弹蚁咬一下，相当于被800伏电了一下。”

解析：

```json
{
  "data_entity": "子弹蚁痛感类比",
  "translation_type": "cross_domain_analogy",
  "source_value": "子弹蚁咬一下",
  "endpoint_value": "800伏",
  "endpoint_resolution_score": 0.31,
  "resolution_status": "partial_resolution",
  "candidate_value": "800伏",
  "requires_claim_verification": true
}
```

结果：

```text
允许提取：800伏
不重复解释：子弹蚁痛感
不在图片中宣称：800伏等于某种固定痛感
```

#### 5.3.8 精确案例三：现实参照已解决

输入：

> “全世界拥有55万亿元实体现金。它能垒成和东方明珠差不多高的纸币大楼。”

解析：

```json
{
  "translation_type": "concrete_reference",
  "endpoint_value": "东方明珠高度",
  "resolution_status": "full_resolution",
  "cluster_suppressed": true
}
```

结果：

```text
55万亿元不提取
```

### 5.4 必须识别的“指向画面”语言

以下表达说明作者正在让用户看画面，必须触发视觉检查：

```text
这是……
是这样的
现实里是这个样子
模拟出来的样子
你看到的……
像这样
如图
画面里
眼前这个
这里展示的是
能够装下这样一辆……
平铺满……
盖住整个……
叠起来有这么高
放在现实里是……
和你想象的一样吗
```

还应识别语义等价表达，而不是只匹配固定关键词。

例如：

> “而这是100万在现实里面模拟出来的样子。”

这句话不能继续被当作“100万人民币体积仍然抽象”。  
它明确告诉系统：作者正在通过当前画面完成现实模拟。

---

### 5.5 视觉直观化类型

视频画面出现以下任一形式，均视为作者已经直观化。

#### A. 真实物体模拟

- 成捆纸币；
- 实物堆叠；
- 模型摆放；
- 真人与目标对象同框；
- 真实场景中的大小演示。

例：

```text
100万元现金的实际堆放效果
```

#### B. 熟悉物体装载或容量对比

- 一辆运钞车能装多少；
- 一个房间能放多少；
- 一辆卡车、一个瓶子、一个足球场等作为容量参照。

#### C. 比例与高度对照

- 东方明珠；
- 楼层；
- 跑道；
- 人体；
- 地球、月球等同屏比例。

注意：

> 如果参照物本身陌生，但作者已经提供了清楚画面比例，仍视为作者完成直观化，不再重复生成。

#### D. 数量堆叠或复制动画

- 大量车辆图标；
- 人群点阵；
- 钱币数量堆叠；
- 逐步增加的柱状物。

#### E. 时间、概率或风险图示

- 时间轴；
- 100人图；
- 风险区间；
- 颜色梯度；
- 阈值线。

#### F. 文字与画面共同解释

单独看字幕可能仍抽象，但同期画面已经解释。

例：

```text
字幕：“这是1亿元人民币。”
画面：一辆装满现金的运钞车。
```

这属于完整直观化。

---

### 5.6 视觉检查窗口

对每个候选数据，至少检查：

```text
候选出现前 2 秒
+
候选出现时
+
候选出现后 8 秒
```

若当前知识点尚未结束，则继续检查到知识点结束，最长不超过后续 15 秒。

建议抽帧：

- 候选前 2 秒：1帧；
- 候选所在句：2～3帧；
- 候选后 8 秒：每2秒1帧；
- 出现明显转场时额外抽帧。

不能只检查候选出现的单帧，因为作者可能先说数字，后展示对比。

---

### 5.7 语义对齐检查

画面中出现物体，不代表它一定解释了当前数据。

必须判断：

```text
画面对象
+
口播指向
+
当前数据
```

是否属于同一个解释目标。

至少回答：

1. 画面展示的是什么？
2. 它是否直接对应当前数据？
3. 用户是否能从画面获得尺度感？
4. 是否只是无关B-roll或装饰画面？

只有语义对齐后才能抑制。

#### 正例

原文：

> “而这是100万在现实里面模拟出来的样子。”

画面：

> 100万元人民币按真实比例堆放。

结论：

```json
{
  "visual_concretization_found": true,
  "semantic_alignment": "exact",
  "already_concretized": true
}
```

#### 反例

原文：

> “100万人民币有多少？”

画面：

> 普通城市航拍或人物喝咖啡。

结论：

```json
{
  "visual_concretization_found": false,
  "semantic_alignment": "none",
  "already_concretized": false
}
```

---

### 5.8 多模态直观化评分

```text
concretization_score =
0.30 × 口播指向画面的明确程度
+ 0.30 × 画面与当前数据的语义对齐度
+ 0.20 × 用户可直接获得尺度感的程度
+ 0.10 × 对比关系清晰度
+ 0.10 × 画面持续与可见程度
```

判定：

- `≥0.75`：作者已完成直观化，强制取消；
- `0.55～0.75`：不自动触发，仅进入人工复核或知识点列表；
- `<0.55`：视为尚未直观化，可继续评分。

高置信口播指向词 + 明确对应画面时，可直接判为已直观化。

---

### 5.9 文字已具体化的判断

除视觉外，还要检查作者是否已在文案中给出：

- 现实参照；
- 熟悉对象；
- 倍数关系；
- 生活场景；
- 时间跨度；
- 现实结果。

例如：

> “每天花1万元，需要2.4亿年才能花完，比恐龙诞生到现在还久。”

这已经把“900万亿元”用日常花费和历史时间做了直观化，不应再次提取。

纯文案模式下，只要文本明确出现以下任一结构，也应直接抑制：

```text
数据句
→ “那放在现实里是什么概念”
→ 代词或省略主语
→ 现实参照
```

例如：

> “全世界现在一共拥有55万亿元实体的钱。那放在现实里是什么概念呢？它能垒成和东方明珠差不多高的纸币大楼。”

即使没有视频画面输入，也应判断作者已经完成直观化。

---

### 5.10 抑制优先级

以下规则优先于好奇度、抽象程度和生图价值：

```text
只要已经具体化
→ 不提取
```

不得因为：

- 数据很夸张；
- 用户可能好奇；
- 画面还能做得更漂亮；
- 模型可以换一个参照；
- 当前图不够专业；

而再次生成。

如果作者的对比可能不准确，应交给“视频说法验证”链路，而不是重新生成第二套直观化图片。

---

### 5.11 决策矩阵

| 口播有具体化 | 画面有具体化 | 处理 |
|---|---|---|
| 是 | 是 | 强制取消 |
| 是 | 否 | 若文字已足够直观，取消 |
| 否 | 是 | 强制取消 |
| 指向画面但画面不清楚 | 不确定 | 不自动触发，进入复核 |
| 否 | 否 | 允许进入抽象数据评分 |

---

### 5.12 输出字段

每个候选必须输出：

```json
{
  "author_concretization_check": {
    "text_concretization_found": true,
    "deictic_visual_cue_found": true,
    "visual_concretization_found": true,
    "visual_type": "real_object_simulation",
    "semantic_alignment": "exact",
    "concretization_score": 0.94,
    "already_concretized": true,
    "evidence": [
      "口播：这是100万在现实里面模拟出来的样子",
      "画面：100万元人民币按真实比例展示"
    ]
  }
}
```

若 `already_concretized = true`：

```json
{
  "trigger_level": "suppress",
  "visualization": null,
  "image_prompt": null
}
```

## 6. 用户好奇度判断

本 Skill 不只判断“难不难懂”，还要判断用户是否自然想知道。

### 6.1 高好奇数据

通常具备：

- 反常识；
- 数量级极端；
- 与身体感受、风险、痛感、速度或巨大尺度有关；
- 数字决定核心结论；
- 用户很难凭经验估计。

示例：

- 800伏
- 65℃
- 1000亿倍太阳质量
- 0.01秒
- 风险增加20%

### 6.2 低好奇数据

- 日常金额；
- 普通体重；
- 常见时间；
- 普通数量；
- 不影响核心结论的数据。

### 6.3 好奇度评分

```text
curiosity_score =
0.30 × 数量级陌生度
+ 0.25 × 与身体或现实结果的关联
+ 0.20 × 反常识程度
+ 0.15 × 对视频结论的重要性
+ 0.10 × 视觉化收益
```

要求：

- `curiosity_score ≥ 0.72`：可自动轻提示；
- `0.58～0.72`：仅进入本视频知识点列表；
- `<0.58`：不提取。

---

## 7. 多个抽象数据同时出现

一句话可能包含多个数据。

例：

> “子弹蚁咬一下，相当于被800伏电击，疼痛持续24小时。”

候选：

- 800伏；
- 24小时。

一次只选择一个主数据。

### 7.1 主数据选择顺序

1. 哪个最容易引发“这是什么概念”的自然好奇；
2. 哪个最影响当前结论；
3. 哪个最难凭常识理解；
4. 哪个最适合准确直观化；
5. 哪个没有被作者后文解释。

本例优先：

```text
800伏
```

因为它比“24小时”更陌生、更反常识，也更可能引发点击。

### 7.2 次数据处理

- 放入详情页关联补充；
- 或进入本视频知识点列表；
- 不同时弹出多个轻提示。

---

## 8. 参照物选择

参照物必须让数字变得更熟悉，而不是制造第二层抽象。

### 8.1 必须满足

1. 同一维度；
2. 普通用户熟悉；
3. 尺度稳定；
4. 换算准确；
5. 不依赖专业知识；
6. 3～5秒能看懂；
7. 适合统一贴图表达。

### 8.2 熟悉度优先级

```text
身体和日常经验
→ 普遍公共场景
→ 标准单位阶梯
→ 大众熟悉的大尺度对象
→ 著名建筑和冷门地标默认禁用
```

优先：

- 人的身高；
- 一层楼；
- 100米跑道；
- 足球场；
- 一分钟；
- 一小时；
- 一天；
- 常见家用电压；
- 常见饮品温度。

默认禁用：

- 哈利法塔；
- 埃菲尔铁塔；
- 冷门地标；
- 专业设备；
- 用户同样没有尺度感的对象。

---

## 9. 单跳与尺度阶梯

### 9.1 单跳比较

当倍率在 `0.2～20`，且参照物本身足够熟悉时：

```text
目标数据
→ 熟悉参照物
```

### 9.2 尺度阶梯

当直接比较出现大倍数或二次抽象时：

```text
目标数据
→ 中间尺度X
→ 可选中间尺度Y
→ 熟悉基础参照
```

限制：

- 总节点3～4个；
- 最多2个中间节点；
- 每一跳优先2～20倍；
- 单跳不得超过50倍；
- 一张图只允许一条链；
- 累计换算误差不得超过5%。

例：

```text
100米跑道
→ ×10
→ 1千米
→ 约×8.85
→ 珠峰8848.86米
```

不推荐：

```text
珠峰≈88条100米跑道
```

因为“88条”本身又变成新的抽象数量。

---

## 10. 涉及安全或伤害数据的边界

数据直观化不能偷偷完成事实核验。

例：

> “800伏电一下的痛感。”

可直观化：

- 800伏与家用电压的数量级差异；
- 800伏属于高电压尺度。

不可直接生成：

- 800伏等于某种固定痛感；
- 800伏一定会造成某种结果；
- 用电压单独判断伤害。

详情页应提示：

> 实际电击影响还与电流、接触时间、人体电阻和路径有关。

原比喻是否准确，应同时交给“视频说法验证”链路。

---

## 11. 提取与触发评分

### 11.1 抽象数据评分

```text
abstract_data_score =
0.25 × 数量级陌生度
+ 0.20 × 现实尺度缺失程度
+ 0.20 × 对核心结论的重要性
+ 0.15 × 用户好奇度
+ 0.10 × 参照物质量
+ 0.10 × 视觉化收益
- 作者已有解释程度
- 二次抽象风险
- 误导风险
```

### 11.2 阈值

- `≥0.76`：自动轻提示；
- `0.60～0.76`：进入知识点列表；
- `<0.60`：不提取。

安全敏感数据的自动触发阈值提高到 `0.82`。

## 12. 生图画布与区域硬约束

所有最终图片固定输出为：

```text
宽度：310px
高度：180px
方向：横向
宽高比：31:18
```

必须按 310×180 原生小尺寸构图，不得先按大海报逻辑设计后缩小。

### 12.1 固定画布

- 深黑灰色圆角卡片背景铺满画布；
- 四周使用细灰色描边；
- 背景允许轻微中心聚光与柔和暗角；
- 四周保留约 10px 安全边距；
- 不生成手机外框、展示场景、外部留白或额外悬浮卡片；
- 所有关键文字和贴图必须在 310×180 原尺寸下清晰可读。

### 12.2 固定上下分区

卡片永远分为两个区域：

```text
顶部：提问 + 解答固定区
底部：贴图 + 文字动态直观化区
```

推荐区域比例：

```text
顶部问答区：约占画面高度 34%
底部直观化区：约占画面高度 66%
```

参考位置：

```text
顶部问答区：y = 10px ～ 61px
底部直观化区：y = 65px ～ 170px
```

不得将贴图、刻度、箭头或参照物侵入顶部问答区。

## 13. 顶部问答区：结构与位置锁定

顶部问答区的**版式、位置、层级永久固定**，只允许替换问题和答案文案。

### 13.1 固定结构

```text
第一行：问题
第二行：答案
```

不放置：

- “AI知识点”标签；
- 栏目名；
- 图标；
- 贴图；
- 来源；
- 额外解释；
- 第二副标题。

### 13.2 问题

固定要求：

- 位于卡片左上方；
- 单行显示；
- 白色超粗无衬线字体；
- 必须是用户自然会问的问题；
- 直接包含当前抽象数据；
- 结尾优先使用问号；
- 视觉字号约 18～22px；
- 建议不超过 12 个汉字，极限不超过 15 个汉字。

示例：

```text
65℃有多烫？
800伏是什么概念？
珠峰8848米有多高？
```

### 13.3 解答

固定要求：

- 紧贴问题下方；
- 单行显示；
- 浅灰色中等字重；
- 先直接回答问题，不复述问题；
- 只写一个核心结论；
- 视觉字号约 9～12px；
- 建议不超过 18 个汉字，极限不超过 24 个汉字。

示例：

```text
已经明显烫口，可刺激食管
远高于日常家用电压
接近9个1千米高度
```

### 13.4 问答区锁定字段

```json
{
  "qa_region": {
    "locked": true,
    "position": "top",
    "question": "65℃有多烫？",
    "answer": "已经明显烫口，可刺激食管"
  }
}
```

模型不得改变：

- 问题在上、答案在下的顺序；
- 问答区位于卡片顶部；
- 左对齐的基本关系；
- 问题比答案更醒目的层级；
- 问答区与下方直观化区的分离关系。

## 14. 底部直观化区：内容与布局动态生成

底部区域根据当前抽象数字的特征动态决定：

- 使用什么贴图；
- 使用几个节点；
- 是否需要刻度线；
- 是否需要箭头或倍率；
- 哪个节点高亮；
- 每个节点配什么文字；
- 节点如何排列。

顶部问答区固定，底部不得反过来支配或挤压顶部。

### 14.1 动态内容选择原则

底部内容必须服务于：

> 用最少的贴图和文字，让用户快速形成当前数字的现实尺度感。

每个贴图必须满足：

- 与当前数据直接相关；
- 普通用户容易识别；
- 不需要额外背景知识；
- 不制造第二层抽象；
- 能在小尺寸下保持轮廓清晰；
- 不只是装饰。

### 14.2 动态布局类型

布局不固定为某一种，但必须从数据本身出发选择最合适的表达方式。

#### A. 刻度分档型

适用于：

- 温度；
- 速度；
- 风险等级；
- 电压区间；
- 阈值变化。

结构：

```text
水平刻度线
+
3～4个分档节点
+
目标节点高亮
```

#### B. 并列参照型

适用于：

- 金额规模；
- 重量；
- 面积；
- 数量；
- 同量级对象比较。

结构：

```text
3个并列贴图节点
+
每个节点一个参照与短结论
```

#### C. 尺度阶梯型

适用于：

- 高度；
- 距离；
- 极长时间；
- 极大或极小数量。

结构：

```text
熟悉基础尺度
→ 中间尺度
→ 目标尺度
```

总节点 3～4 个，最多 2 个中间节点。

#### D. 单核心 + 辅助参照型

适用于：

- 一个目标数字是绝对视觉中心；
- 只需要两个参照即可解释；
- 并列节点会削弱主值。

结构：

```text
目标数字或目标贴图居中突出
+
左右各1个辅助参照
```

#### E. 比例或人数图型

只适用于：

- 概率；
- 风险；
- 百分比；
- 人群比例。

没有可靠基线时禁止使用。

### 14.3 节点数量

- 默认 3 个节点；
- 只有天然分档内容允许 4 个节点；
- 禁止 5 个及以上节点；
- 无法放下时优先减少节点，不得缩小文字硬塞；
- 每张卡片只解释 1 个核心数据。

### 14.4 节点文字

每个节点根据空间决定使用：

```text
数值或对象名
主解释
可选副解释
```

限制：

- 数值或对象名：不超过 7 个汉字；
- 主解释：不超过 6 个汉字；
- 副解释：不超过 8 个汉字；
- 三节点可保留主、副两行；
- 四节点优先只保留数值与主解释；
- 不写完整长句；
- 不添加脚注、来源或括号说明。

### 14.5 贴图画风固定

底部贴图内容动态变化，但画风永久统一：

```text
精致扁平卡通贴纸风，
轻微2.5D体积感，
明显白色粗外描边，
细深灰内描边，
圆润简化造型，
轻微立体阴影，
柔和局部高光，
颜色鲜艳但不过度饱和，
轮廓清楚，
无写实纹理，
无复杂背景。
```

所有贴图必须像来自同一套贴图库。

### 14.6 高亮规则

当存在明确目标值时：

- 只高亮一个核心节点；
- 使用浅橙色、暖黄色或与主题匹配的圆角描边框；
- 高亮框可包围数值、贴图和节点文字；
- 不使用霓虹光、强发光或复杂装饰；
- 非目标节点不得同时抢夺视觉焦点。

### 14.7 底部布局计划字段

生成最终 Prompt 前，必须先输出：

```json
{
  "visual_region": {
    "position": "bottom",
    "layout_type": "scale_marker",
    "node_count": 4,
    "highlight_node": 3,
    "connector": "horizontal_gradient_scale",
    "nodes": [
      {
        "label": "37℃",
        "sticker": "闭眼微笑的舒适人物半身贴纸",
        "main_text": "接近体温",
        "sub_text": "感觉温热"
      }
    ]
  }
}
```

## 18. 质量检查

输出前逐项检查：

1. 是否有明确数字；
2. 是否有单位、比例、概率、倍数或阈值；
3. 是否排除了普通生活数据；
4. 是否排除了机制、名词和主题；
5. 用户是否真的缺少尺度感；
6. 用户是否可能自然产生好奇；
7. 作者是否已经做过对比或解释；
8. 是否等知识点讲完后再判断；
9. 是否选择了同维度且熟悉的参照物；
10. 是否避免第二层抽象；
11. 大倍数是否改用尺度阶梯；
12. 是否区分直观化和事实核验；
13. 是否能在3～5秒内看懂；
14. 是否只有一个核心数据；
15. 生图提示词是否保持统一风格；
16. 是否明确指定310×180像素与31:18横向比例；
17. 是否按原生小尺寸构图，而不是大图缩小；
18. 是否只使用3～4个贴图节点，优先3个；
19. 标题是否单行且不超过11个汉字；
20. 四节点时是否删除非必要说明；
21. 所有内容是否位于10px安全边距内；
22. 文字和贴图是否在310×180原尺寸下清晰可读；
23. 是否没有手机外框、外部场景或额外留白；
24. 是否识别了“这是、像这样、模拟出来、放在现实里”等画面指向表达；
25. 是否检查了候选前2秒到后8秒的画面；
26. 是否判断画面与当前数据语义对齐；
27. 是否区分真实模拟、数量堆叠、熟悉物体对比和无关B-roll；
28. 作者已经直观化时是否强制取消；
29. 视觉证据不确定时是否避免自动触发；
30. 是否按知识点而不是单句判断；
31. 是否识别“它、这个数字、这些钱、这笔钱”等跨句指代；
32. 是否识别“那放在现实里是什么概念”等解释意图；
33. 是否等待解释闭环结束后再提取；
34. 后文未重复数字但给出参照时，是否正确关联回原数据；
35. 同一数据出现任一有效参照后，是否强制抑制；
36. 是否识别“相当于、约合、折合、按照购买力算、按汇率算、也就是”等换算表达；
37. 是否将原始值、换算值、类比值合并为同一解释链；
38. 是否正确区分受众本地化、现实参照、尺度换算、跨领域类比和重复重述；
39. 是否判断解释终点，而不是看到“相当于”就直接抑制；
40. 完全解决时是否抑制整个数据簇；
41. 部分解决时是否只评估最后未解决节点；
42. 是否避免同时提取原始值与换算值；
43. 是否识别引用前文已直观化对象的情况；
44. 跨领域类比涉及安全或科学准确性时，是否转交说法验证链路；
45. 是否通过100万、55万亿元、10万亿美元、800伏和1光年回归测试；
46. 是否严格输出310×180原生尺寸；
47. 顶部是否只包含问题和答案；
48. 问题是否始终在答案上方；
49. 问答区的位置和层级是否锁定；
50. 贴图、刻度或箭头是否没有侵入顶部问答区；
51. 底部布局是否根据当前关键内容动态选择；
52. 是否逐节点详细描述贴图、文字、位置和高亮；
53. 是否避免只写“3个节点横向排列”这种空泛结构；
54. 是否只高亮一个目标节点；
55. 是否输出完整视觉描述型Prompt及负面提示词；
56. 是否将保留候选和抑制候选分开输出；
57. `source_span` 是否为原文连续且逐字一致的片段；
58. 是否禁止模型自己生成概括性候选名称；
59. 是否先为每个数字标注角色；
60. 是否只有 `unresolved_candidate` 进入 `selected_candidates`；
61. 是否将同一实体、指标和时间范围聚合为一个数据解释簇；
62. 是否把人均结果、货币换算、铺满面积等识别为作者解释证据；
63. 是否避免把解释证据重新组合成更长候选；
64. 是否将“从A缩水到B并最终破产”识别为变化事件；
65. 当所有数据已被解释时，是否正确输出空数组；
66. 是否通过3000万亿元、214万元、马斯克身家和雷曼市值回归测试。

任意一项不通过，必须排除或重新生成。

## 20. 本段金融文案的强制判定示例

针对以下内容：

```text
超过3000万亿元
→ 平均给每个中国人214万元
→ 平铺满一整个网球场

马斯克八九千亿美元
→ 接近波兰一年GDP
→ 突破万亿美元
→ 财产能盖住纽约市

雷曼市值从300多亿美元缩水到几十亿
→ 最终破产
```

正确结果：

```json
{

  "suppressed_candidates": [
    {
      "source_span": "超过3000万亿元",
      "reason": "同一数据簇已通过人均214万元和网球场完成直观化"
    },
    {
      "source_span": "214万元",
      "reason": "属于作者解释3000万亿元的中间换算结果，不是新候选"
    },
    {
      "source_span": "八九千亿美元",
      "reason": "已与波兰一年GDP进行比较"
    },
    {
      "source_span": "万亿美元",
      "reason": "属于马斯克身家同一时间演进簇，且后文已用纽约市覆盖面积直观化"
    },
    {
      "source_span": "从300多亿美元缩水到几十亿",
```

以下五种输出必须判为错误：

```text
全球金融资产超3000万亿元
3000万亿资产平分中国人，人均214万元，纸币铺满网球场
```

- 不是原文原子片段；

- 将作者解释证据重新包装成候选；
- 忽略同一数据簇已经完成直观化；
- 把变化事件误当成尺度好奇点。

## 22. 最终执行指令

1. 按时间戳切分视频字幕、OCR、画面与知识点；
2. 扫描明确数字、单位、比例、倍数、概率和阈值；
3. 为每个数字定位原文连续片段；
4. 验证 `span_verbatim = true`，非原文改写候选直接作废；
5. 为数字标注角色：
   - `source_data`
   - `author_translation`
   - `concrete_reference`
   - `comparison_baseline`
   - `change_endpoint`
   - `real_world_outcome`
   - `background_context`
   - `unresolved_candidate`
6. 按“实体 + 指标 + 时间范围 + 语义目标”建立数据解释簇；
7. 识别跨句指代、解释意图、单位换算、货币换算、现实参照和画面模拟；
8. 将同一事实的原始值、平均值、对比值、结果值和视觉参照合并进同一簇；
9. 等待解释闭环结束，不得在数字首次出现时提前选择；
10. 判断解释链终点：
    - `full_resolution`
    - `partial_resolution`
    - `no_resolution`
11. 簇内出现有效现实参照、画面模拟或作者本地化换算时，标记 `full_resolution`；
12. `full_resolution` 时抑制整个簇，包括其中的原始数字和中间换算数字；
13. `partial_resolution` 时最多评估最后一个未解决原子数据；
14. 不得将作者解释句、参照句或多个数字拼成一个新候选；
15. 对“从A到B、最终出现结果”的变化事件默认抑制；
16. 只有角色为 `unresolved_candidate` 的原子数据才进入抽象性和好奇度评分；
17. 一条解释链最多输出一个候选；
18. 未解决候选通过阈值后，生成固定顶部问答区：
    - 问题在上；
    - 一句直接解答在下；
19. 根据关键数字动态选择底部贴图、节点、刻度、阶梯或比例布局；
20. 逐节点输出位置、贴图主体、状态、标签、主文字和副文字；
21. 生成完整视觉描述型生图 Prompt；
22. 卡片严格为310×180像素；
23. 将可展示内容放入 `selected_candidates`；
24. 将已解释、已换算、变化事件和普通数据放入 `suppressed_candidates`；
25. 当没有合格候选时，`selected_candidates` 必须输出空数组；
26. 严格按JSON输出，不得为了数量强行提取。
